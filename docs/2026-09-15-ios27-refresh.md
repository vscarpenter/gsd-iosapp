# iOS 27 / macOS 27 refresh: decisions

Date: 2026-09-15. Release: 3.0.0 (34). Branch: `feat/ios27-refresh`.
Brief: the September 15 refresh review and its per-repo kickoff (`design_handoff_ios27_refresh/`).

## The stance

Selective Liquid Glass. System chrome (toolbars, the tab bar, the sidebar, sheet grab regions)
takes the material the OS gives it. Everything Inkwell owns stays opaque: `surfaceCard()`, the
quadrant washes, sheet content, and the matrix. PRODUCT.md carries this as design principle 6
so parity work never glasses the content layer to match iOS.

## Toolchain

- Xcode 27.0 (27A266a), Swift 6.4, iOS 27.0 SDK and simulator runtime.
- `SWIFT_VERSION` in `project.yml` stays "6.0". The brief asks for 6.4, but that setting is
  the language mode, and the compiler accepts only 4, 4.2, 5, and 6. Xcode 27 supplies the
  6.4 compiler on its own. A comment beside the setting says so.
- The deployment floor stays at iOS 26.0 and macOS 26.0. The SDK drives the new look.
- All three targets built with zero errors and zero project warnings on the 27 SDK before any
  source change. The `@State` macro coexists with the property wrapper in SwiftUICore, and the
  app's `State(initialValue:)` sites (`GSDApp.swift`, `SmartViewEditorView.swift`) compile
  untouched.
- No "iPhone 17 Pro" simulator exists on the 27.0 runtime. Builds and captures use iPhone 18
  Pro and iPad Pro 13-inch (M5) on iOS 27.0.

## Scene lifecycle

The app already runs on the scene-based lifecycle: the SwiftUI `App` plus an
`AppDelegate` that answers `configurationForConnecting` with `QuickActionSceneDelegate`.
Quick actions arrive through the window scene (cold launch via `connectionOptions`, warm via
`windowScene(_:performActionFor:)`). The `AppDelegate` copy of `performActionFor` was the
pre-scene path and is dead in a scene-based app, so it is gone. `LiveWebAuthPresenter`
resolves its anchor from `connectedScenes`, and the Share Extension hosts a view controller,
which the requirement does not touch.

## Visual baseline

`scripts/capture-screens.sh <label> [iphone|ipad|mac]` runs
`ScreenshotTests/RefreshBaseline.swift`: the seeded app with a frozen clock, one PNG per
screen, light and dark, on iPhone, iPad, and Mac Catalyst. Output lands in
`build/screens/<label>/`, which is gitignored. The pre-change set is `build/screens/baseline`.
Every later phase compares its touched screens against it.

What the baseline showed before any change:

- The 27 SDK already renders the floating glass toolbar buttons and the floating tab bar with
  no code change. The serif titles survive.
- On iPad the sidebar's selected row now renders as an opaque pill in the app tint (ink), so
  the selected label was ink on ink and unreadable in both appearances. Before the 27 SDK this
  happened only on Catalyst, which the code already handled.

## Phase 1: glass where the system gives it

- `AppAppearance.configure()` no longer builds `UINavigationBarAppearance` or
  `UITabBarAppearance` objects. It sets the serif title attributes on the navigation bar
  proxy and leaves the bar and tab-bar material to the system. On the 27 SDK the change is
  invisible on iPhone (every light screen pixel-identical to the baseline) and the serif
  titles still render, so the simpler code stays.
- The selected sidebar row now draws its label and symbol with `.primary` instead of a
  guessed on-accent color. The selection fill moved in both directions this cycle: opaque
  ink on iPad (the old code kept ink text, unreadable) and a neutral fill on macOS 27 while
  the sidebar is unfocused (the old Catalyst-only paper text painted white on light).
  `.primary` follows whichever fill the system paints.
- The sidebar's Matrix row carries the four-pigment mark (`LaunchMark`) instead of a gray
  grid symbol. Smart-view rows keep their existing identity pigments; Dashboard, Archive,
  and Settings stay graphite. No new colors.
- PRODUCT.md principle 6 records the opacity rule.

## Container reordering: evaluated, not adopted

`reorderContainer(for:move:)` with `.reorderable()` is real and would work on the matrix grid
and the smart-view lists. It is not adopted this cycle:

- In-quadrant order is derived, not stored. `TaskStore.tasks(in:showCompleted:)` sorts by
  `updatedAt` with completed tasks last, and smart views sort by their criteria. Nothing in
  the task model holds a position.
- A manual order needs a persisted field. That field would have to reach the backup envelope
  and the PocketBase wire model for the web and Android clients to agree, which is exactly
  the three-repo contract change the brief rules out.
- Cross-quadrant drag stays as it is: it flips the urgent and important flags, it does not
  move a position.

Revisit only as a cross-platform spec item with a stored order in all three clients.
